# 质检 Checklist

带 10 人团队时每天用的抽检单。合格率低于线就全检，不赌。

## A. 格式（机器可查，先跑脚本）

- [ ] JSON / JSONL 能解析
- [ ] 必填字段齐全（id / conversations / tags 等）
- [ ] id 无重复
- [ ] from 取值合法（system/human/gpt）
- [ ] 空字符串 / 纯标点回复 = 0 条

## B. 指令遵循（抽检重点）

- [ ] 字数在要求区间（自己数，不目测）
- [ ] 必含要素逐项打勾
- [ ] 禁用词搜一遍（Ctrl+F）
- [ ] 输出格式与要求一致（列表/表格/字数/语言）
- [ ] 多轮第 N 轮没丢第 1 轮的约束

## C. 事实

- [ ] 专有名词（人名/书名/公司/年份）抽查
- [ ] 数字能复算的复算
- [ ] 前提错误的题，模型是否纠正而不是顺着编
- [ ] 不确定的标"待核"，不装懂

## D. 安全

- [ ] 危险操作没有给可执行参数
- [ ] 隐私（身份证/住址/病历）未出现在交付里
- [ ] 该拒的拒了，且给了合法替代
- [ ] 违法用途（诈骗话术、洗钱帮手）直接打回

## E. RLHF 专项

- [ ] choice 与 dimensions 多数派一致（除非一票否决并写明）
- [ ] rationale 里有具体指令点/事实点，不是"质量更高"
- [ ] 连续 10 条同选 A 或同选 B → 停，复查
- [ ] 平局率在合理区间（异常高 = 没拆维度）

## F. 团队流程

- [ ] 新人上岗前做过 5 条校准题
- [ ] 当日打回的 case 当日进 badcase 库
- [ ] SOP 改了要群通知并记版本
- [ ] 抽检比例不低于项目约定（常用 5%–10%）

## 打回话术（对事不对人）

> 这条打回：字数 140 / 要求 180–220，指令遵循不过。参考 SOP §2 和 case-01 的 B。改完我 10 分钟内复检。

不写："你这什么态度""怎么又错"。
