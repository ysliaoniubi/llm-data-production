# 数据采集规范

用于为训练/评测准备原始语料与任务素材。采集不是"能爬就爬"，是**带着验收标准去拿数据**。

## 1. 采集前先写四件事

1. **用途**：SFT / RLHF / 评测集 / 检索库，用途决定清洗强度
2. **目标量与配比**：多少条、什么领域、什么难度
3. **来源白名单**：允许的网站/API/自有数据，禁止的来源（需登录的个人数据、明确禁止抓取的站点）
4. **合规底线**：不采个人隐私（身份证、住址、病历）、不采侵权内容用于训练发布、遵守 robots 与服务条款

## 2. 常见采集类型（对应简历工作内容）

| 类型 | 采什么 | 验收 |
|---|---|---|
| 指令/对话 | 公开问答、论坛高赞讨论改写成指令 | 改写后无原帖用户信息；一源一许可记录 |
| 写作素材 | 产品说明、活动通知、公众号文章结构 | 只采结构与手法，正文需改写或授权 |
| 评测题干 | 学科真题风格改写、场景题自拟 | 不直接照抄付费题库 |
| 市场信号 | 公开行情、资金费率、持仓（加密/金融研究） | 标时间戳与来源 URL，可复拉 |
| 标注任务包 | 图片/文本/语音的采集清单 | 每条带采集时间、设备/来源、初筛标签 |

## 3. 采集流程

```
写采集单（用途/量/来源/字段/禁止项）
  → 小批量试采 50–100 条
  → 验收样例（字段齐不齐、脏数据比例）
  → 通过后放量
  → 去重（URL、正文 hash、近似 title）
  → 打标（领域、语言、质量初筛 pass/review/drop）
  → 交付 csv/jsonl + 采集说明
```

## 4. 字段最小集

```json
{
  "id": "crawl-2026-11-18-0001",
  "source": "example.com",
  "url": "https://…",
  "captured_at": "2026-11-18T14:00:00+08:00",
  "lang": "zh",
  "domain": "finance",
  "text": "…",
  "quality": "pass",
  "notes": "含表格已转 markdown"
}
```

## 5. 脏数据处理

| 情况 | 处理 |
|---|---|
| 正文是评论水贴 | drop |
| 广告/导流 | drop |
| 需要登录才完整 | drop 或标注 incomplete |
| 编码乱、表格碎 | review，能修复则修复 |
| 与已有集重复 | 去重，保留最早/最全版本 |

## 6. 金融/链上公开数据（可复现）

以 Hyperliquid 公共 info API 为例（无需鉴权）：

```
POST https://api.hyperliquid.xyz/info
{"type": "metaAndAssetCtxs"}
```

采集脚本只做三件事：定时拉、写带时间戳的 jsonl、字段不加工（加工放分析层）。这样别人能用同一脚本复现同一批数。

## 7. 验收标准

- 采集说明齐全（来源、时间、脚本或方法）
- 抽 30 条：字段完整率 ≥ 98%
- 重复率 ≤ 3%
- 无明确违规来源
- 试采未过不批量
